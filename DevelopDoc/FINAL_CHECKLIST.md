## 0. 이 문서 사용법

**왜 필요한가**: WORK_UNITS는 작업 단위 하나하나가 끝났는지를 판단한다. 이 문서는 **프로젝트 전체가 "완성"이라고 말할 수 있는지**를 판단한다. 작업 단위가 모두 끝나도 서로 연결했을 때 빠진 것이 없는지, 발표·제출 전에 한 번에 확인한다.

**판단 기준**
| 결과 | 조건 |
|---|---|
| ✅ **v1.0 완료** | §1~§14의 **필수(●) 항목이 모두 체크**되고, §16 최종 승인이 끝남 |
| 🟨 조건부 완료 | 필수 항목 중 미완료가 있으나 사유·대응이 §15에 기록되고 현준님이 승인함 |
| ⬜ 미완료 | 그 외 |

**표기**
| 기호 | 뜻 |
|---|---|
| ● | 필수 — 하나라도 빠지면 완료 불가 |
| ○ | 권장 — 빠지면 사유를 §15에 기록 |
| 증거 | 확인한 근거 (PR·테스트 결과 파일·캡처·로그 위치). **증거 없는 체크는 무효** |

**점검 방법**
1. 검증/문서 담당이 항목마다 실제로 확인하고, 증거 칸에 위치를 적는다.
2. 운영 주소(`*.vercel.app`)에서 확인해야 하는 항목은 **로컬이 아니라 운영 주소**에서 확인한다 (🌐 표시).
3. 점검은 `main` 브랜치의 최종 커밋 기준으로 하고, 커밋 번호를 §16에 적는다.

> **v0.4.0 점검 기준 (2026-10-01)**: `main` @ `83933e1` (Phase 4 병합). 자동 테스트 수는 단위 1,310 · 회귀 28 · 화면 157 (HANDOFF §0.1). Phase 5 병합 뒤 최종 커밋에서 CI·배포 줄은 다시 본다.
> 증거 칸 기호: 🟨 일부만 있음 · 👤 사람이 대시보드에서 확인 · ⏭ 앞으로 할 일(리허설·사용자 테스트 등). 체크하지 못한 ● 항목은 모두 §15에 있다.

1. 비로그인 화면 → 로그인 유도
2. 구글 로그인 → 빈 대기화면
3. 단순 질문 ("SK하이닉스 최근 실적 어때?") → 좌 차트 / 우 분석 글, 사용된 데이터
4. 기간 지정 질문 → 지정 기간으로 조회
5. 복합 질문 → 계획 카드 → 승인 → 진행 → 실행 기록 → 뉴스 단서 (취소도 한 번 시연)
6. 금융사 포함 비교 → `※` 주석, 자기자본비율 그래프
7. 보드 필터 변경 → 차트·표 동시 변경
8. 재실행 → 같은 숫자 (재현성)
9. 다른 계정으로 남의 분석 주소 접근 → 거부
10. 서비스 범위 밖 질문("파이썬 코드 짜줘")·투자 권유 요청("지금 사도 돼?") → 공손한 거절 안내 (AI 오남용 방지)
